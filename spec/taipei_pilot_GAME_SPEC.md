## 1. 一句話目標

兩個孩子各拿一支手機當操縱桿，在電腦大螢幕上各開一架 voxel 飛機從松山機場起飛，在半徑 10 公里的台北上空找地標、完成任務，學會「從天上看台北長什麼樣子」——101 在哪、河往哪流、機場跑道為什麼是一條直線。

## 2. 設計決定快查

| 設計點 | 決定 |
|---|---|
| 平台架構 | **獨立 web 專案**（不進 kids_arcade）：電腦瀏覽器全螢幕 3D 主畫面 + 手機瀏覽器遙控頁（掃 QR 即連，免裝 app）+ 本機 WebSocket relay server，全部同一 Wi-Fi 【§10-1】 |
| 3D 引擎 | **Three.js**：voxel 箱體幾何 + 低解析貼圖 + 像素化材質（`NearestFilter`），Minecraft 式點陣風 |
| 連線 | WebSocket relay（電腦開 server → 螢幕顯示 QR → 手機掃碼進遙控頁）；**2 個控制器 slot**，先連先佔、斷線重連回原機 |
| 操控 | **手機傾斜 = 操縱桿（拍板）**（roll 左右傾=轉彎、pitch 前後傾=俯仰）+ 螢幕油門豎滑桿 + 校正歸零；備案=螢幕虛擬搖桿（協定不變）。**遙控手機 = iPhone + Android 混合（拍板）** → server 自簽 HTTPS、iOS 權限彈窗流程 |

| 視角/雙人呈現 | **左右分屏（拍板）**，各自追焦鏡頭；單人連線自動滿版 |
| 第一架飛機 | **T-34C 初級教練機（拍板）**：紅白塗裝、單螺旋槳、串列雙座；voxel 模型 accent 色 = slot 色（紅機/藍機） |

## 3. 核心循環（一個任務）

```
電腦開遊戲頁（全螢幕）→ 螢幕顯示大 QR code ×2
   ↓
孩子各自用手機掃 QR → 手機變成遙控器（顯示自己的飛機顏色 + 油門滑桿）
   ↓
兩架飛機停在松山機場跑道上（10 跑道頭，朝西）
   ↓
教學瞬間（首次）：「推油門到底，飛機跑起來就會飛上天！」
   ↓
起飛（油門推滿 → 加速 → 自動離地，孩子體會「快到一定程度才飛得起來」）
   ↓
任務出現：「找到台北 101，從旁邊飛過去！」＋目標方向箭頭
   ↓
飛行（傾斜轉彎 + 俯仰，找地標）
   ── 接近任意地標 → 浮出地名牌（voxel 立牌）
   ── 撞建築/壓太低 → 彈開 + 手機震動 + ❤️ −1
   ── ❤️ 歸零 → 「回機場休息一下」→ 重新從跑道起飛，❤️ 補滿
   ↓
飛進目標光圈 → 達成！地標亮起 + fact 揭曉（「101 有 101 層樓！」）
   ↓
下一個任務（持續供題；雙人時任務各自獨立，互不卡關）
   ↓
全部地標點亮 → 「🎉 台北飛透透」大慶祝（夜景 + 煙火）
   ↓
（隨時）按手機「降落」引導鍵 → 跑道進場提示 → 成功落地 = 落地大拍手
```

> 一個任務約 1–3 分鐘。起飛 ≤ 15 秒就要在空中（6 歲注意力）。

## 4. 規則 / 資料模型

### 4.1 飛行規則（6 歲優先，街機式）

- **傾斜操縱桿**（手機 DeviceOrientation）：roll → 轉彎（自動協調，帶傾斜視覺）、pitch → 爬升/俯衝；死區 + 靈敏度經 L-1 spike 調校
- **油門滑桿**（手機螢幕右側豎滑）：0–100%；跑道上油門滿 + 速度夠 → 自動離地（不用拉桿，降低起飛挫折）
- **自動保護**：放手回平飛（水平儀自動回中）、最低高度自動拉起（不會直接栽地，但貼地飛過久警告）、最高雲頂蓋、空域邊界（10 km）= 柔和回頭提示「台北在那邊～」+ 自動緩轉回
- **降落輔助**：按「降落」→ 螢幕畫進場走廊光圈序列，跟著穿過即自動對正，接地判定寬鬆
- 速度區間鎖定：永遠不失速、不解體；快慢只影響轉彎半徑與風聲

### 4.2 空域與碰撞

- 半徑 10 km 圓形空域，圓心 = 松山機場（25.0694°N, 121.5521°E）
- 高度層：地面 0 → 雲頂 ~600 voxel-m；建築最高 = 101（給「繞過它還是飛過它」的選擇）
- 碰撞體：建築 AABB、地形；**兩架飛機互相穿透**（幽靈模式，避免兄弟互撞變吵架來源）
- 違規/撞擊共用 ❤️ 計數，預設 3、設定頁可調 1–5/無限（沿用小司機拍板 #13 的旋鈕哲學，prefs 存 localStorage）

### 4.3 任務型

| 型 | 玩法 | 教育目標 |
|---|---|---|
| 地標尋寶 | 「找到圓山大飯店，從旁邊飛過」目標光圈在地標旁 | 鳥瞰地標辨識 + 方位感 |
| 穿圈航線 | 沿河/沿路一串光圈（淡水河 5 連圈）| 河流/幹道走向的身體記憶 |
| 高度挑戰 | 「飛到比 101 還高！」/「低低地沿著基隆河飛」 | 高度概念 |
| 起降練習 | 回松機落地（進場走廊輔助）| 跑道方位 + 完整飛行循環 |

### 4.4 資料模型（TypeScript/JS）

```js
// airspace.json —— 一份檔案 = 一個空域（未來高雄小港、台中清泉崗 = 內容包）
{
  id: 'taipei',
  name: '台北',
  center: { lat: 25.0694, lng: 121.5521 },   // 松山機場
  radiusKm: 10,
  runway: { heading: 100, lengthM: 2605, label: '10/28' },  // 松機真實諸元
  rivers: [ /* 淡水河、基隆河、新店溪 折線 → voxel 水帶 */ ],
  landmarks: [
    { id: 'taipei101', name: '台北 101', pos: [x, z], heightClass: 'tower',
      voxelModel: 'taipei101.vox', fact: '101 有 101 層樓！',  // DRAFT
      missions: [...] },
  ],
  blocks: { seed: 42, density: ..., palette: 'taipei' },  // 程序化街區參數
  missions: [ { id, type, targetId|rings[], prompt /*DRAFT*/, order } ],
}

// 控制協定（手機 → relay → 螢幕，30Hz）
{ slot: 0|1, roll: -1..1, pitch: -1..1, throttle: 0..1, btn: { land, horn } }
```

## 5. 視覺與互動設計

- 主題：**點陣積木城 (voxel-toybox)**。Minecraft 式方塊語彙，但色票走玩具櫃柔和路線：草地 `#9DBF7B` 系（與玩具墊呼應）、河流粉藍、建築糖果色系、地標用辨識色（101 = 青綠）
- 像素紀律:材質 `NearestFilter` 不抗鋸齒、貼圖 16×16、模型皆方塊組合（含飛機）;太陽光 + 柔和環境光,長影斜照(下午四點的台北)
- 飛機 voxel 模型：~200–500 方塊，螺旋槳動畫（轉速跟油門）、傾斜帶 banking 視覺
- **電腦螢幕（橫式 16:9）**：

```
┌─────────────────────┬─────────────────────┐
│  P1 鏡頭（追焦第三人稱） │  P2 鏡頭             │
│  任務卡(上)  ❤️❤️❤️    │  任務卡(上)  ❤️❤️❤️   │
│        目標方向箭頭     │                     │
│   高度帶(右緣細條)      │   高度帶             │
└─────────────────────┴─────────────────────┘
        （單人連線時 P1 滿版；分屏為 §10-5 建議案）
```

- **手機遙控頁（直式）**：上半 = 自己飛機顏色 + 姿態小圖（傾斜跟著動，孩子確認「這是我」）；右側 = 油門豎滑桿（拇指）；下方 = 「降落」「喇叭🎺」兩大鍵（≥ 64dp）；撞擊時 `navigator.vibrate`
- 鏡頭：第三人稱追焦（飛機在畫面下 1/3，前視偏移看得到要飛去哪）；轉彎時鏡頭平滑追趕（沿用小司機三修的減暈參數哲學）
- 互動規格沿用 DESIGN_CRAFT_GUIDE 精神：按鍵 TactilePress 形變回饋（web 版用 CSS transform 重做）、落地 Settle 著地感、目標圈 success 粒子
- **隨空域變動的視覺資產（教訓 B1，一律參數化）**：地標模型、街區色票、河流折線、跑道諸元、教學文案、milestone 文案——全部吃 `airspace.json`，引擎零改動換城市

## 6. AI — 無模型，純規則

- web 平台不帶 Gemma（端側模型是 Flutter app 的資產）；問答型任務 Wave 這版不做，避免無 grounded 安全網的生成內容（教訓 B4/B5 的反向應用：沒有三件套就不上生成）
- 適應性任務挑選 = 純 JS：先近後遠、先大後小（101 早於紅樓）、失敗回填簡單任務；雙人各自獨立供題
- 未來若加「塔台語音」等生成玩法 → 走 server 端 API + grounded 紀律，另開 spec 修訂

## 7. 資料層與儲存

- **localStorage**（無 SQLite、無 migration——本款不碰玩具櫃 db，鐵律 §12 自然滿足）：

```js
'tp_landmarks_lit'   // ['taipei101', ...] 點亮過的地標
'tp_missions_done'   // ['m01', ...]
'tp_mishap_limit'    // 3（設定頁可調）
'tp_plane_color'     // per-slot 機身色
'tp_celebrated'      // 大慶祝一次性 gate（沿用小司機 J 的一次性哲學）
```

- 進度存在「電腦」端（螢幕是狀態的家，手機是無狀態搖桿——換手機掃碼不掉進度）

## 8. 雙人模式（本款核心，不是 Polish）

- **2 controller slots**：QR 掃進來先佔 slot 0（紅機）、後佔 slot 1（藍機）；第三支手機掃碼 → 「機庫滿了，下一班再來」
- 合作不競爭：任務各自獨立供題、地標點亮全家共享（誰點亮都算）、大慶祝一起看
- 斷線處理：手機鎖屏/離開 → 該機自動回平飛盤旋 10s 等重連；逾時 → 溫和降落消失，slot 釋出
- 單人也完整可玩（slot 1 空 → P1 滿版）；**爸爸的手機可以當第二機**——這就是「跟小孩玩」的設計原點

## 9. 開發階段拆解（5 階段，Stage L）

> 本款 agent sandbox **可以自己跑**（Node + 瀏覽器，無 Flutter 限制）——CI 紀律改為：vitest 單元測試 + Playwright 連線整合測試本地全綠才交；**真雙手機手感仍是 Sung HITL，不可 proxy（鐵律 2）**。

| 階段 | 內容 | 估時 |
|---|---|---|
| **L-1** 連線+操控 spike | **GO/NO-GO spike：WebSocket relay + QR 連線 + 手機傾斜 → 螢幕 3D 方塊即時動（延遲體感）+ 雙手機同連互不干擾 + DeviceOrientation 權限/HTTPS 實測**（Sung 兩支真機親驗）；NO-GO 備案 = 螢幕雙虛擬搖桿 | 1.5 天 |
| **L-2** 飛行核心 | 街機飛行模型（轉彎/俯仰/油門/自動保護）+ voxel 飛機（機種依 §10-4）+ 起飛/降落判定 + 追焦鏡頭 + 平地測試場 + vitest | 2.5 天 |
| **L-3** 台北空域 | `airspace.json` 管線 + 松機跑道/河系/8–10 地標 voxel 模型 + 程序化街區 + 碰撞 + 效能（兩鏡頭 60fps）| 3.5 天 |

| **L-5** Polish | 音效（引擎 loop/風聲/落地拍手）+ 教學瞬間 + 設定頁（❤️ 上限/機身色）+ 台北飛透透大慶祝 + DRAFT 校稿清單 + QA | 1.5 天 |
| **合計** | | **~11.5 天 part-time** |
